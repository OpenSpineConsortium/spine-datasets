Every set on the grid carries a freeze (tools/freeze.py): FROZEN.json and FROZEN.files.tsv.gz beside the data, a public copy as frozen/<id>.json, and its bytes, files and tree_sha256 in the record's measured; read sizes from these, never by walking the tree.

The owner asked on 2026-10-23 that every dataset put on the grid come with a file that freezes its tree and hashes it, so the copy is shown identical and its size and shape are read at once. The tree hash is the sha256 of the sorted file list (sha256, bytes, path per line), so one hash stands for every name and byte, and each folder has its own. The public copy names nothing below the top folders, since spine-datasets is public and a held set may name subjects in its paths. The promoter freezes each set it installs from the hashes it has just checked and brings frozen/<id>.json in its record update; the 101 sets that landed before are listed by `tools/freeze.py plan` and frozen by grid/freeze.sh, only on the owner's word with the job count. CephFS gives a folder's bytes and file count natively (ceph.dir.rbytes, ceph.dir.rfiles), which the quota work in SchwingNet uses; the freeze adds identity and the outline that GitHub can show. The thread's note is symphony-template docs/research/frozen-dataset-manifests.md.
