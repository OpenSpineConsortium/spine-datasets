The census counts every dataset from its one record, datasets/<id>.json, and folds in only the records that are new or changed, so no dataset is passed over twice (the owner's ask of 2026-10-23, issue #178).

tools/census.py reads the records alone, never a dataset's files: a dataset's bytes are read once, when they land, by the promoter or the owner's own chain, and what that pass measured is written into the record. Each run of .github/workflows/census.yml reads the last census.json on the branch census, carries every record whose sha256 did not change, derives a row again for the rest, and logs what moved with the date; it writes census.json, CENSUS.md and census.html there, and docs.yml folds the same way onto that ledger for the docs site's /census.html. The rules a row is derived by are the code of tools/census.py and tools/pipeline.py, fingerprinted in census.json: a change to either derives every row afresh on the next run with one log entry, and a record whose content did not change keeps its date of last change. Each record keeps the date the census first saw it, even when it is removed and written again.

A record carries what the census needs: the status `held` for a set on the grid by the owner's chain and not the promoter (a history entry and a grid_path under the owner's grid root or home or the shared tree with it, which tools/dataset_review.py flags for whoever merges to check against a listing of the grid; only the promoter writes `fetched`), counts under the standard keys subjects, xray_images (still images), videos (a run, clip or sweep once), run_frames (the frames inside those, apart from still images), ct_volumes and bytes (the older names are read as aliases, by the kind of set), measured.bytes for the size on the grid, and, on a real X-ray set with the same subject's CT, a `pairing` block placed after `group` whose tier (A on the grid, B open or granted, C asked or to ask, D refused or embargoed, E a pair of something other than the spine) follows the status by itself. A task issue whose body says "Record: datasets/<id>.json" with no such file yet is listed as pending, among the pairs when it carries the label paired. The record format is datasets/README.md; `python3 tools/census.py check` runs in scripts/check.sh.
